# 行为规格

## 收藏数据获取

- 打开弹窗时异步读取当前范围，读取期间不能使用上一范围的候选池。已有完整数据时可以直接抽卡，并核验远端第一页。每种收藏状态在一次页面加载内至多自动核验一次：核验一致或全量网络获取成功后，再次打开或切换到该状态不再自动核验；核验或其触发的网络更新失败时，下次进入重新核验。
- 核验比较首页指纹；本地和远端总页数可信且可比较时，也比较总页数。变化后后台全量更新，并复用同一任务已验证的首页响应；手动全量更新和失败后的新一轮任务不复用旧任务响应。首页及页数不变不能保证所有后页均未变化。
- 每种状态所有页面获取并校验成功后，整体替换本页候选数据。保存失败不阻断抽卡，也不破坏数据库中的旧完整记录；网络失败、取消或残缺数据不能替换旧候选。
- “全部收藏”须五种状态均有完整数据，空收藏也是完整数据；数据可来自已读缓存或本页完整获取结果，每种状态分别发布，不要求同一轮完成。一种状态失败时，仅取消依赖本次“全部”获取且没有独立需求的任务。
- 一个页面内至多同时进行四个列表请求。当前范围的列表工作优先；切换状态不取消旧状态的独立任务，关闭弹窗也不中断获取。评分请求不占列表名额，不提供停止按钮。列表请求超时从实际发出时开始计时。
- 已知总页数时可并行获取剩余页面；未知时逐页发现。空首页只在分页信息允许时视为有效空收藏；重复的非空页、矛盾分页、异常 HTML 和超过安全上限的页数不能发布为完整收藏。

## 失败和重试

- 当前范围获取失败时提示后续操作：有完整缓存可继续使用缓存，也可点击“全量更新”。仅后台任务失败不打断已完成的当前范围。
- 403、5xx、429 等 HTTP 错误在首次响应时即失败，不自动重试，不依据 `Retry-After` 等待。429 会停止当时本页面全部列表工作，但**不锁定后续尝试**：切换到失败的状态会正常重新获取；当前范围失败后关闭再重开会自动重试。仅后台失败时，重开不使已完成的当前范围重新获取。用户也可以点击“全量更新”显式重试。
- 失败后重开并开始自动重试时，隐藏旧失败操作框；再次失败再显示。错误日志保留，登录提示、完成通知和进度按原有优先级展示。

## 本地缓存

- 收藏和评分使用当前 origin 的 IndexedDB；三个匹配域名各自存储。只在首次打开弹窗后读库，已加载的完整快照留在本页内存。存储不可用时仍可通过网络获取并抽卡，页面离开后未保存的数据可能丢失。
- 写入以事务成功提交为准，失败保留旧记录并给出独立的非阻断提示。“重试保存缓存”只保存本页最新待保存数据、必要时重新开库，不重新抓取收藏，不向 localStorage 写入，也不自动循环重试。升级时关闭旧连接；阻塞、异常关闭或超时均可提示后重试。
- 当前范围优先导入有效旧缓存，再后台分批迁移本脚本已识别的同源旧缓存。只补缺，不覆盖已有完整收藏或有效评分；导入失败可只读复用旧数据。成功提交后删除对应旧键；删除前核对源值未变。确定过期、损坏或不完整的已识别旧记录可删除，未知键和未来版本记录保留。
- 首次打开弹窗后至多安排一轮后台维护：完成旧数据迁移并分批清理过期评分，不等待维护结果才展示或抽卡。收藏不按存放时间删除。清理失败只记录诊断信息，不抢占进度、不弹操作框、不循环重试。
- 不协调跨标签页请求、实时同步或任务先后顺序；数据库同一记录以最后成功提交者为准，各页继续使用自身已加载快照。

## 抽卡与评分

- 抽卡开始时固定候选快照；后台收藏数据更新不改变本轮结果。评分缓存自获取成功起有效 72 小时，迁移、收藏全量更新和手动刷新均不重置有效期。
- 登录页、验证页和无法识别或不匹配的条目页不视为成功评分结果，不写入有效评分缓存。合法条目页确实没有评分仍可缓存；历史上已通过数据校验且未过期的评分不统一清空。评分获取成功不能因保存失败降为黑卡。
